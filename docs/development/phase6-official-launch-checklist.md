# Phase6 — 正式公開チェックリスト

**公開日当日にチェックする。**  
前提: `/owner/launch-verdict` が **🟢 正式公開**（全KPI公開基準・サンプル充足）。  
1項目でも 🟡/🔴 なら本チェックリストに進まない。

判定画面: `/owner/launch-verdict`  
KPI定義: `docs/development/phase6-launch-verdict.md`

使い方: 公開日に上から順に `[ ]` → `[x]`。未完了が1つでもあれば公開しない。

---

## 0. 公開ゲート（必須・最初に実施）

- [ ] `/owner/launch-verdict` を開いた時刻を記録した（UTCまたはJST）
- [ ] 公開判定が **🟢** である
- [ ] 改善が必要なKPIが **なし** である
- [ ] 依頼数サンプル ≥ 50（画面の仕事完了率・エラー率の母数）
- [ ] 初回成功率の母数 ≥ 50
- [ ] NPS回答数 ≥ 30
- [ ] 直近24時間に本番障害・重大インシデントがオープンでない（`/owner/reliability` / 監視）

**ゲート未達 → 公開中止または延期。以下は実施しない。**

---

## 1. 技術

- [ ] 本番デプロイ対象コミットSHAを記録した
- [ ] 本番ビルドが成功している（CI green）
- [ ] 本番環境変数が揃っている（`/owner/env-status` で必須項目が不足ゼロ）
- [ ] Stripe モードが意図どおり（live / test）である（`/owner/billing-webhook` 等で確認）
- [ ] OpenAI（または使用中LLM）APIキーが本番用で有効である
- [ ] DB / ストレージ接続が本番向けである
- [ ] マイグレーション適用済みで未適用ゼロである
- [ ] 招待制フラグ / 機能フラグの本番値が公開方針と一致（`/owner/feature-flags`）
- [ ] 本番で「写真→資料」1件が完了し、成果物が開ける（実測1件）
- [ ] 本番でログイン → 依頼 → 完了の所要秒数を記録した
- [ ] Word / 成果物ダウンロードが成功する（`/owner/diagnostics/word-download` で異常なし）
- [ ] `/status`（またはステータスページ）が 200 を返す
- [ ] 外部サービス一覧に Critical 障害がない（`/owner/external-services`）

---

## 2. UX（公開導線のみ・改修はしない）

- [ ] 未ログインからトップへ到達できる
- [ ] 初回ユーザーが「何を終わらせますか？」を5秒以内に理解できる導線になっている（実測: 社外1名または録画）
- [ ] チュートリアル・営業ウィザードが初回を阻害しない
- [ ] 完了画面に「お仕事が終わりました」「開く」が出る
- [ ] 失敗時にユーザーが次の一手（続ける / 別の写真）を選べる
- [ ] モバイル幅で依頼→完了が最後まで通る
- [ ] 利用規約・プライバシーへのリンクがフッターまたは導線から開ける

**UXの「改善案レビュー」はしない。数字が悪いKPIだけ別タスク化する。**

## 3. 法務

- [ ] 利用規約（`/terms`）が公開版として最終確定している
- [ ] プライバシーポリシー（`/privacy`）が公開版として最終確定している
- [ ] 特定商取引法表記（該当ページ）が公開版として最終確定している
- [ ] 問い合わせ窓口（`/contact`）が到達可能である
- [ ] 個人情報の保存・削除手順が文書化されている（アカウント削除導線を確認）
- [ ] 外部AIへのデータ送信範囲がポリシー文面と一致している
- [ ] 未成年・禁止用途の記載がある（規約上）
- [ ] 法務担当（またはCEO）が「公開版OK」と署名/記録した（氏名・日時）

## 4. 課金

- [ ] 本番 Stripe の商品・価格IDが公開プランと一致している
- [ ] チェックアウトがテストカード以外で1件成功している（またはliveで検証済み）
- [ ] Webhook が本番URLを向き、直近イベントが受信できている（`/owner/billing-webhook`）
- [ ] 無料→有料の切替後、権限が即時反映される
- [ ] 解約 / 期間末キャンセルの動作が確認済みである
- [ ] 決済失敗時のユーザー表示と再試行導線がある
- [ ] 返金・クレーム時の社内手順（誰が・何時間以内）が1枚で存在する
- [ ] 税率・表示価格（税込/税別）が法務・画面で一致している
- [ ] `/owner/launch-verdict` の課金率が公開基準である（二重確認）

## 5. 通知

- [ ] 障害・重大エラーの通知先（メール/Slack等）が本番チャンネルである
- [ ] 課金失敗通知が運営に届く設定である
- [ ] ユーザー向けメール（受付・完了・失敗）が必要なものだけ有効である
- [ ] 誤ってβ招待文面のままのメールテンプレが残っていない
- [ ] 通知の送信元ドメイン / SPF・DKIM が有効である（メールを使う場合）
- [ ] `/owner/notifications` で未処理の重大通知がゼロ、または担当割当済みである

## 公開実行（チェック完了後のみ）
