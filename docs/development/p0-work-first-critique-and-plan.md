> 基準: 世界トップクラス SaaS（Linear / Notion / Canva / Cursor）  
> 方針: 依頼者の希望に合わせない。間違っている指示は実装しない。

---

| 指示 | 判定 |

| 機能追加より削除・統合 | **正しい** |

## 2. 反論（ここは実装しない / 修正してから）

### 2.1 進捗に「Word生成 / PDF生成 / メール送信」と出すな

ユーザー案の進捗 UI は、形式をユーザーに再学習させる。  
「形式を考えさせない」と矛盾する。

世界トップの秘書 UX は内部手段を晒さない。

| 禁止（ツール語） | 採用（秘書語） |
|------------------|----------------|
| Word生成 | 資料を作成しています |
| PDF生成 | お渡し用に整えています |
| メール送信 | お送りする準備をしています（**依頼に送信があるときだけ**） |

**実装しない:** Word/PDF/メールを並べたステップ劇場。

### 2.2 Done に「送信・投稿」を常時必須にするな

依頼に無い送信・投稿まで必須にすると:

- 未接続ユーザーを必ず失敗させる  
- 勝手に送る危険な製品になる  
- 「完了」が嘘つきになる（スキップして completed にするならなお悪い）

**正しい Done:**

```
常に必須: 生成（必要なもの）+ 履歴 + 通知 + 実行証跡
意図があるときだけ必須: 保存 / 送信 / 投稿
```

途中停止で Done 禁止、は賛成。ただし「全 Capability 必須」は反対。

### 2.3 「画像→Word→PDF→保存→通知」を万能の初回導線にするな

これはまだ **生成パイプラインのデモ** であり、Canva 級の Aha（具体的な仕事が終わった）ではない。

問題:

- 誰に送る？どこへ保存？（外部未接続なら「保存」がアプリ内だけになり期待とズレる）  
- すべての初回ユーザーが画像を持つわけではない  
- Word+PDF 両方を毎回出すのはコストと時間を食い、5分体験を壊しやすい  

**正しい初回楔（例・1つだけ選ぶ）:**

> 「短い仕事依頼を書く → 秘書が資料を用意 → アプリ内に保存・履歴・通知まで終わる → 『お仕事が終わりました』」

送信は接続済みかつ依頼に含まれるときだけ。初回強制にしない。

### 2.4 P0 で Decision Engine 全体を載せない

P0 で「AIが毎回フル判断」までやると、また約束が膨らむ。  
P0 の勝ち筋は **削除** と **一本の完了パス**。

AI 本格 Decision は P1（形式セレクタ削除と `auto` のあと）。

## 3. 正しい P0（最小変更・今やる）

### 体験の定義

```
ユーザー: 仕事を書く（形式を選ばない）
  → 常に preferredFormat=auto
  → 既存 work job / Commander / deliverables
  → 秘書語の進捗
  → 生成 + 履歴 + 通知までで「お仕事が終わりました」
  （送信は依頼+接続があるときだけ）
```

### コード変更（今回）

1. `HomeChatBar` / `WorkRequestForm` から成果物形式セレクタ削除  
2. submit は常に `preferredFormat: "auto"`  
3. コピーを仕事依頼へ（placeholder / hint）  
4. クイックプリセットを「仕事」語に寄せ、画像生成プリセットを外す  
5. 反論と計画を本ドキュメントに固定  

### 直後の P0 続き（次コミット候補・まだ大きく作らない）

1. Workspace 進捗を秘書語の段階表示に（内部の docx/pdf 名を出さない）  
2. 完了カード文言「お仕事が終わりました」+ 履歴リンク  
3. LP の未実装メトリクス削除（約束を縮める）  
4. 楔ジョブ1本の初回導線（オンボーディングをその1本に固定）  
5. `completed` を証拠ゲートで禁止（送信は意図があるときのみ）

### やらない（明示）

- メール送信を初回必須にする  
- Word/PDF ステップ名の可視化  
- Capability 全開の Decision Engine  
- 新連携の追加  
- 新料金プラン

---

## 4. 成功判定（P0）

1. ホームに Excel/Word/PDF セレクタが無い  
2. 新規ユーザーが形式を選ばずに依頼できる  
3. 完了時に「ファイルがある」だけでなく履歴・通知まで届く（既存経路の確認）  
4. 進捗に開発者語・形式名が並ばない（続きタスク）  
5. LP ができないことを約束しない（続きタスク）

---

## 5. 一文

あなたの方向（秘書・完了・削除優先）は正しい。  
間違っているのは **完了の過剰定義** と **手段名を進捗に晒す UI** と **万能デモ導線**。  
世界トップは「全部やる」ではなく「一本の正直な完了」で勝つ。
