## ① UI — 38

### 創業者
迷わない UI ではない。ホーム依頼バーに **テキスト + 画像 + ファイル + 成果物形式 + お願いする** が並ぶ。Linear/Notion の「一つの明確な行為」に遠い。  
削除すべき UI の筆頭:

1. **成果物形式セレクタ（Excel/Word/PDF）** — 秘書をツールに戻す装置  
2. ランディングの **架空ダッシュボード指標**（Today saved 4h、Confidence 98%）— 未実装の期待値インフレ  
3. サイドバーに並ぶ複数の「仕事の顔」（依頼 / 定期 / 覚えた仕事）が初週で多すぎる  
4. ベンダー露出（Clerk 文言、技術スタック信頼帯）— 秘書ブランドを薄める

### VC
UI の問題は美しさより **情報設計の未決断**。何が Primary Action か決まっていない製品はスケールしない。

### 一般ユーザー
「自動判定 / Excel / Word / PDF」を見た時点で、「あ、自分で選ぶアプリなんだ」と学習する。その学習を後から秘書に戻すコストは高い。

## ② UX — 36

依頼→完了がストレスゼロか？ **No。**

実態フロー（単発）:

1. 書く  
2. 添付する（必要な仕事では必須）  
3. 形式を選ぶ（任意だが目立つ）  
4. 別画面/ジョブ待ち  
5. プレビュー・ダウンロード  
6. 送信や保存は別途・未接続・未完了になり得る  

「仕事を頼むだけ」になっていない。  
ユーザーが考えさせられること:

- 何形式か  
- どこまでやってくれるのか  
- 連携は要るのか  
- 終わったのか部分なのか  
- 次に何を押せばいいのか  

世界トップ（例: 「Canva でデザインして共有」）は、初回の成功パスが一本。MINERVOT はパスが枝分かれしたまま「秘書」と名乗っている。

## ③ AI秘書 / 差別化 — 42

| 競合 | 差別化は十分か | 現実 |
|------|----------------|------|
| ChatGPT | **不十分** | 初回体験が「聞いて書く」に見える |
| Claude | **不十分** | 長文・資料品質では負けやすい。完了出口が無いと勝負にならない |
| Gemini | **不十分** | Workspace 内完了（Gmail/Drive/Calendar）に原生で負ける |
| Copilot | **不十分** | Word/Excel/Outlook の庭そのもの |

「これなら MINERVOT」と言える条件は一つしかない:

> **ChatGPT では面倒な『承認→送信/保存→証跡→次回も同じ』が、ここなら終わっている。**

今はその条件を **毎回・確実に** 満たしていない。思想ドキュメントは 80 点、製品体験は 40 点台。

## ④ 完了品質 — 34

Done 定義（生成+保存+送信+通知+履歴+証跡）は設計上正しい。  
採点は実装の強制力で行う。

甘い点:

- 生成成功で「完了した」と感じさせる UI が残る  
- 外部未接続でも期待値を上げすぎるコピーがある  
- ランディング例に `upcoming` / `partial` が混在  
- first-success 体験にフォールバック完了の余地（デモ完了は毒）

途中で止まる設計: ある（承認・連携・形式・画面遷移）。止まってよいのは **承認だけ**。それ以外の停止は欠陥。

## ⑤ 信頼性 — 41

| 観点 | 評価 |
|------|------|
| 毎日使えるか | 個人なら可。ジョブ基盤は育っているが単発は `after()` 依存が残る |
| 法人 | **まだ無理**（監査・権限・SSO・保持・SLA が製品として語れない） |
| エラー復旧 | リトライ思想はある。ユーザー向け「どこで止め・どう再開」は弱い |
| 証跡 | 設計中心。ユーザーが監査できる UI ではない |
| 監査 | 法人要件未達 |

VC 視点: 「信頼性は機能ではなく契約」。今は契約以前。

## ⑥ 継続率 / ¥980 — 33

Light ¥980 の中身（現状の売り方）:

- 文章作成  
- SNS 投稿補助  
- 自動化 3 件  
- AI 回数 120  

これは **AIツールの容量プラン** であり、秘書の「仕事が終わった回数」プランではない。

半年後も使う理由になり得るもの:

- 毎週同じ仕事が、自分の癖で自動実行される  
- 未完了がない  
- 通知で確認するだけ  

それが弱いと解約理由は明確:

1. ChatGPT で足りた  
2. 連携が面倒  
3. 期待した「送るまで」が終わらない  
4. 毎月の上限が先に来る（価値よりメーター）  
5. 毎日開く理由がない（ホームが薄い）

毎日起動理由: **今日の仕事** コンポーネントはコード上あるが、現行ホームに載っていない。継続設計が UI に接続されていない。

## ⑧ ブランド — 40

強み: 「AIチャットではない。専属秘書」は物語として良い。

弱点:

1. **MINERVOT** — 発音・意味・記憶負荷が高い。グローバルで説明コストがかかる（Figma/Notion は音が軽い）  
2. **ATLAS / MINERVOT / atlasapp.jp / minervot.app 表記ゆれ** — ブランド未決のにおい  
3. 世界観はコピーにあるが、プロダクト表面がツール UI で世界観を否定する  
4. 「世界へ行けるか」— 今のままでは No。縦の完了ブランドに振り切れば Yes の余地

## ⑩ 致命的な弱点 — 今すぐ売れない原因

売れない原因は機能不足ではない。

### 本当の原因（優先順）

1. **約束と初回完了の乖離**  
   LP: 最後まで仕事を行う / 節約時間ダッシュボード  
   アプリ: 形式選択つき依頼フォーム  
2. **wedge（最初に殺す仕事）がない**  
   全員の秘書 = 誰の必需品でもない  
3. **収益モデルがツール課金**  
   ¥980 が「回数」で、完了アウトカムと未接続  
4. **手段を選ばせる UI がカテゴリを自己否定**  
5. **ブランドとドメインと内部名の分裂**  
6. **法人信頼の欠如**（証跡・権限・監査が製品化されていない）

新機能を足すほど、この6つは悪化し得る。

## P0 / P1 / P2 / P3

### P0（絶対・今すぐ）— 新機能禁止。約束を縮め、完了を一本化

1. **初回成功パスを1本に固定**（例: 「営業メール下書きを作って確認まで」or「週報を作って保存」— 1つだけ）  
2. **成果物形式セレクタを主UIから削除**（詳細に隠す or 廃止）  
3. **LPの未実装メトリクス/過大コピーを削除**（嘘を売らない）  
4. **Done ゲートをコードで強制**（証拠なし completed 禁止）  
5. **ICP を一文で決める**（例: ひとり営業の週次報告を終わらせる）  
6. **ATLAS/MINERVOT 表記のユーザー向け統一**

### P1（3か月以内）

1. 実行計画の提示→承認→実行（Decision Engine 最小）  
2. 出口1つを本物にする（Gmail 送付 **または** Drive 保存）  
3. 「今日の仕事」をホームに戻し、毎日開く理由を作る  
4. ¥980 を「完了できる仕事」の言葉で再定義（回数メーターを前面から下げる）  
5. 類似仕事「前回と同じ流れで？」  
6. 失敗時の人間向け再開 UI

### P2（半年以内）

1. 定期実行の完了率を業務級に（単発も durable drain）  
2. Work Memory → 次回計画の自動注入  
3. 証跡エクスポート（個人事業・小規模法人の最低ライン）  
4. テンプレ3種だけ縦に深い  
5. 紹介導線（完了カードの共有可能な「終わった事実」）

### P3（後回し）

1. Slack/Teams/Discord/Notion 等の横展開  
2. 画像/動画生成の推し  
3. グローバル本格展開・多言語  
4. 高額 Premium の多機能詰め込み  
5. 「何でもできる」カタログ増設

## 最大の欠点（1つだけ）

# **初回5分で「仕事が最後まで終わった」を証明できないこと。**

これがすべてを決定づける。

- UI がツールに見えるのも  
- ChatGPT と並ぶのも  
- ¥980 が払われないのも  
- 口コミが生えないのも  
- 大手に言語を奪われるのも  

根は同じで、**約束した価値（完了）を、最初のセッションで物理的に見せていない**ことにある。

設計書の Decision Engine も Smart Templates も、初回完了が無い限り競争力をほぼ上げない。  
逆に、楔となる仕事1つで「頼んだ → 計画 → 承認 → 保存/送信証拠 → 通知」までを初回で通した瞬間、点数が跳ねる。

**その1つを改善せよ。機能を増やすな。完了を見せろ。**
