# 【ATLAS機能評価】P1-06 分散Rate Limit + 全AI経路適用

機能名：分散 Rate Limit（DB SoT）と全 AI 入口への強制適用

ユーザー価値：サーバーレス複数 instance でも利用上限が効き、急激な連打による停止・課金爆発を防ぐ。秘書として安定して動き続ける。

差別化：インスタンス局所の「見せかけ制限」ではなく、Production DB を正本にした横断制御。

繰り返し作業の削減：一部 — 障害復旧や再試行の手戻りを減らす（直接の習慣作業削減より運営安定）

AI必要度：不要 — カウンタ加算・窓判定は通常プログラム

AIなしで実装可能：はい — Postgres 原子 RPC + repository

運営コスト：AI 追加呼び出しなし。リクエストごとに 1 DB round-trip（RPC）

外部APIコスト：無（Supabase 既存）。逆に OpenAI 枯渇リスクを下げる

コスト削減案：

- [x] エコモードで足りるか — レート制限自体がコスト防御
- [x] まとめて生成できるか — 該当なし（入口制御）
- [x] キャッシュ再利用できるか — window カウンタを DB で共有再利用
- [x] 予約実行にできるか — 該当なし
- [x] AI起動条件を絞れるか — 全 AI 入口で先に consume
- [x] 外部APIの呼び出しタイミングを最小化できるか — 429 で LLM 前に遮断
- [x] 完全自動ではなく承認後実行にできるか — 該当なし（防御機構）
- [x] 同じ処理を再生成しない設計にできるか — 原子 consume で二重加算レースを防ぐ

優先度：P1
