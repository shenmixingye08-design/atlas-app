# MINERVOT CEOレビュー（超辛口・機能追加禁止）

視点: OpenAI / Notion / Linear / Cursor / Figma のCEOが、残り資金で勝たなければならないときに下す判断。  
禁止: 称賛、機能追加、「十分です」。  
許可: 削除、集中、価格の再定義、約束の縮小。

---

## ① 今すぐ消す機能

CEOなら、次を **今すぐ消す / 前面から撤去する**。

1. **成果物形式セレクタと「作る形式」訴求**  
   理由: カテゴリを AIツールに戻す。秘書を殺すUI。

2. **ランディングの未実装ダッシュボード / 節約時間 / Confidence 演出**  
   理由: 信頼を先に使い果たす。初回で嘘がバレる製品はチャーンが確定する。

3. **「できること」カタログの upcoming / partial 展示**  
   理由: メニューを増やして決断を先送りしている。売れない会社の典型。

4. **画像生成を前面に出す導線・プリセット**  
   理由: 手段であり仕事ではない。Copilot/ChatGPTの土俵に自分から座る。

5. **ホームに載っていない「今日の仕事」「記憶パネル」など半分実装の面**  
   理由: コードはあるが体験に接続されていない。保守コストだけ吸う死に機能。

6. **料金面での「AI回数・連携数・SNS件数」メイン訴求**  
   理由: 秘書ではなくメーター販売。¥980の解約理由を自分で作っている。

7. **Automations / 覚えた仕事 / 依頼 が別館に見える多画面並列**（初週導線から外す）  
   理由: Primary Action が複数ある製品は、どれも選ばれない。

消すのは「コード削除」だけではなく、**売らない・見せない・約束しない**を含む。

## ② 絶対に死守する機能（1つだけ）

# **非同期の仕事実行 → 完了通知 → 結果が残る、という一本の依頼完了パス**

（現行: work job 受付 → Commander/実行 → 通知 → 結果/履歴）

理由:

- これが無いと ChatGPT と同一カテゴリになる  
- 秘書の定義は「会話」ではなく「預かった仕事が戻ってくる」こと  
- 記憶も自動化も、この完了パスの上にしか乗らない  

死守するのは Word でも Vision でも課金でもない。  
**頼んだ仕事が、ユーザーの手元で終わったと分かる経路**だけ。

## ③ 企業文化の禁止事項

1. **便利だから作るは禁止**  
2. **競合と同じ画面を真似て追いつくは禁止**  
3. **「将来対応」「一部対応」を製品面に出すのは禁止**  
4. **できないことを LP で約束するのは禁止**  
5. **手段（Word/PDF/モデル名）をユーザーに選ばせるのは禁止**  
6. **証拠なしで完了と言うのは禁止**  
7. **全員の秘書を名乗るのは禁止**（楔の仕事が決まるまで）  
8. **機能追加でレビュー点を稼ごうとするのは禁止**  
9. **内部コードネームとブランドの分裂を放置するのは禁止**  
10. **エンジニアの興味で横の連携を増やすのは禁止**  

文化の一文:

> We delete until the product finishes one job honestly.

## ④ OpenAI が明日同じ機能を出したら勝てるか

**今のままでは、勝てる理由はない。正直に言う。**

OpenAI が「依頼→実行→通知」を出したら、モデル・習慣・配信・信頼で負ける。

勝てると言える唯一の条件（現時点では未達）:

> **特定の仕事タイプにおいて、完了率・再作業率・承認手数で、OpenAI より毎週確実に終わらせていること。**  
> かつ、そのやり方がそのユーザーの記憶としてロックインされていること。

言語（AI秘書）では勝てない。  
完了の深さだけが勝因になり得る。今それは証明されていない。

## ⑤ ¥1,980 / ¥2,980 / ¥4,980 を払う理由はあるか

**現状の売り方では、ない。**

足りないもの:

- 「回数」ではなく **終わった仕事の確実性**  
- 毎週発生する具体仕事の代行（例: 週報が月曜に揃う）  
- 失敗しない完了（途中でユーザーに形式や連携の宿題を出さない）  
- 払わないと困る依存（記憶・テンプレ・証跡）

¥980 は「試す値段」。  
¥2,980+ は「人の代わりに終わらせる値段」。  
後者を正当化する完了実績が製品に無い。

## ⑦ 残り3か月・エンジニア1人・新機能禁止で売上最大化

命令はこれだけ:

### Week 1–2: 約束を切れ
- LP の嘘・未実装を削除  
- 形式セレクタ削除（進行中）  
- 画面を「依頼する」1つに圧縮  

### Week 3–6: 楔を1つに固定して完了率を取れ
楔候補は **1つだけ選ぶ**（例: 週次報告を作って保存・通知まで）。  
既存の依頼→ジョブ→通知→履歴だけで回す。  
送信が未接続なら売らない。嘘の完了を出さない。

### Week 7–10: その楔だけで課金を再定義
- Free: 楔を週N回まで体験  
- Paid: 楔の定期実行 + 優先完了  
回数メーターを前面から外せ。

### Week 11–12: 有料転換の導線だけ磨く
新規獲得を広げない。  
楔が刺さったユーザーに「毎週やる」を既存 Automations で接続し、有料化。

KPI は1つ: **楔仕事の完了率（証拠付き）と有料転換**。  
それ以外の数値は見るな。

## ⑧ 最大の無駄

# **「思想・設計・半分実装・LP約束」を同時に広げ、完了を証明しない開発スタイルそのもの。**

コードの特定ファイルより悪い。  
UI の多さより悪い。  
一番時間を溶かしているのは:

> 世界観ドキュメントと将来アーキテクチャを厚くし、初回5分の完了を薄くしていること。

二番目は、接続されていない機能面（今日の仕事、記憶、カタログ、複数料金訴求）の保守。

## ⑨ このまま続けた場合、1年後に失敗する原因（3つ）

1. **カテゴリ自殺** — ツールUIのまま「秘書」を言い続け、ChatGPT の下位互換と認識される  
2. **楔なし拡散死** — 全業界・全連携を追い、どれも完了率が低い  
3. **信頼破産** — LPと実装の乖離、未完了の completed、チャーンと口コミの不発
