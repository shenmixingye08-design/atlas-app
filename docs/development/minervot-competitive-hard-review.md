# MINERVOT 競争レビュー（忖度なし）— 2026 → 2031

> 目的: 「OpenAI / Anthropic / Google など主要 AI アシスタントと比べ、5年後も選ばれるために何が足りないか」を厳しく洗い出す。  
> 前提: 実行型AI秘書（Work → AI計画 → 承認 → 完了証拠）は正しい勝ち筋。**正しさと勝つことは別**。

---

## 0. 結論（先に刀）

今の MINERVOT は「思想は尖っているが、市場で勝つプロダクトとしてはまだ弱い」。

ChatGPT / Claude / Gemini を正面から「より賢いチャット」で殴っても負ける。  
勝つなら **業務システムの書き換え**（依頼・承認・実行・証跡・記憶・請求）に振り切る必要がある。

現状の最大リスクは次の3つ:

1. **完了まで実行できる統合が、設計書より実装が浅い**（生成は強いが、送信・保存・提出の“仕事の出口”がまだ点在）  
2. **データと信頼の堀が浅い**（Work Memory はあるが、ユーザーが「手放せない」水準の業務グラフになっていない）  
3. **大手が Agent / Computer Use / Workspace 連携で同じ物語を語り始めたとき、差別化言語が溶ける**

5年後も選ばれる条件は「モデルが賢い」ではない。  
**その会社の仕事のオペレーティング・システムになっているか**である。

---

## 1. 競合を正しく定義する

| プレイヤー | 実際の戦場 | MINERVOT がぶつかる点 |
|-----------|-----------|----------------------|
| OpenAI (ChatGPT + Agents) | 汎用エージェント、アプリストア、記憶、タスク | 「頼んだら進めてくれる」体験の同質化 |
| Anthropic (Claude + Computer Use) | デスクトップ操作、コーディング、長文業務 | “最後までやる”の実装力 |
| Google (Gemini + Workspace) | Gmail/Docs/Drive/Calendar の内側 | 保存・送信・予定のネイティブ完了 |
| Microsoft (Copilot + 365) | Word/Excel/Outlook/Teams の内側 | 成果物生成の本丸を既に占有 |
| Notion AI / Zapier Agents / Make | ワークフロー自動化 | 「手順の自動生成＋実行」 |
| 国内縦型SaaS | 請求・ entree・SNS運用など | 業務深度とコンプライアンス |

MINERVOT が「チャットUIの日本版」に見える瞬間、比較対象は ChatGPT になり、**価格・モデル・習慣で負ける**。

---

## 2. 技術 — 厳しい指摘

### 2.1 まだ「生成エンジン付きオーケストレータ」である

設計上の Done（生成+保存+送信+通知+証跡）に対し、実装の重心はまだ:

- 文章/資料生成  
- ファイル export  
- 通知  

に寄っている。Gmail/Drive/Dropbox/X はあるが、**任意の依頼から Capability を選び、承認し、証拠付きで閉じる**一本の高速道路になっていない。

改善:

- Capability Registry + Decision Engine を実装の中心に据える（本追加設計）  
- `completed` を証拠ゲートなしで返せないようにする（技術的強制）  
- 単発ジョブを automation jobs 並みの durable 実行に揃える

### 2.2 モデル競争では勝てない（勝たなくてよいが、依存は危険）

2026 時点でフロンティアモデルの差は週単位で埋まる。  
MINERVOT が特定モデル名や「より賢い要約」を前面に出すほど、コモディティ比較に沈む。

改善:

- モデルは裏側の交換部品（既方針を徹底）  
- 価値指標を「正答率」ではなく **完了率 / 再作業率 / 承認までの手数** に置く  
- 評価セットを自社の仕事ログ（匿名化）で持つ

### 2.3 信頼・権限・監査が「秘書」の致命点

外部送信を自動化するなら、競合以上に:

- 最小権限  
- 宛先確認  
- 実行証跡  
- 撤回/補償  
- テナント分離  

が必要。ここが甘いと、個人利用のおもちゃで終わり、法人に売れない。

改善:

- 計画承認を危険 Capability で必須化（設計済み — 実装を強制）  
- 証跡の改ざん耐性（誰が・いつ・何を・どの証拠で）  
- 企業向け: SSO、監査エクスポート、保持期間

### 2.4 データ面の堀が弱い

Work Memory / Learning の思想は正しい。  
しかし堀になるのは「メモがある」ことではなく:

- その会社のテンプレ  
- 修正履歴  
- 承認パターン  
- 取引先・フォルダ・トーン  
- 失敗からの回避  

が **グラフとして蓄積され、次回の計画に自動注入される**こと。

現状はドメインはあっても、Decision Engine への閉ループが設計段階。  
閉ループが無い記憶は、ただのログである。

## 3. UX — 厳しい指摘

### 3.1 まだ「ツールの顔」が残っている

ホームの成果物形式セレクタ、Word 進捗の個別感、Automations が別館に見える構造は、  
ユーザーに「自分で手段を選ぶ製品」だと学習させる。

秘書なら初週で習慣づけすべき学習は一つだけ:

> 意図を書く → 計画を見て承認する → 終わる

改善: Phase 1 で形式選択を主位置から消す。計画承認を主役にする。

### 3.2 「待つ」体験がプロダクトになっていない

非同期は技術的にあるが、ユーザーから見た「秘書に頼んだ感」は:

- 今何をしているか（日本語ステップ）  
- いつ終わりそうか  
- 承認が必要になったら割込む  
- 終わったら結果の場所が一意  

が揃って初めて成立する。  
ポーリング中のローディングだけでは ChatGPT の「生成中」と区別がつかない。

### 3.3 空の秘書は無能に見える

連携未接続の状態で「送って」と頼まれたとき、  
黙ってファイルだけ返すのは秘書として失格（過剰に完了を装うのも失格）。

改善: 計画段階で「メール送付には Gmail 接続が必要」を出し、接続→同じ計画再開。

### 3.4 日本語の一流秘書トーンは資産だが、速度と簡潔さが足りないと飽きられる

丁寧さは差別化になり得る。長すぎる報告は逆効果。  
完了報告は「何を・どこへ・証拠」の3点に圧縮すべき。

## 4. ビジネス — 厳しい指摘

### 4.1 「誰の予算で買われるか」が曖昧

個人の ChatGPT 代替なら価格競争。  
SMB の「秘書代わり / 業務オペレーション」なら、月額は **人件費の代替** で説明できる。

今の見せ方が生成ツール寄りだと、客は「ChatGPT Plus でよくね？」と言う。

改善:

- ICP を絞る（例: ひとり法人 / 営業事務 / 士業補助 — どれか）  
- 価値訴求を「作成」ではなく「完了件数・削減時間」に  
- 成功事例はファイル形式ではなく「送付まで終わった仕事」

### 4.2 切り替えコストが低い

記憶とテンプレと証跡が弱いと、解約されても痛くない。  
堀は請求書データでもモデルでもなく、**その組織の仕事のやり方の再現コスト**。

### 4.3 統合の保守コストが利益を食う

Slack/Teams/Discord/Notion/Drive/… を全部「ready」にするのは、スタートアップが死ぬ典型。

改善:

- Capability は `planned` を公言してよい  
- ICP が使う出口だけ `ready` にする（例: Gmail + Drive + 通知）  
- それ以外は「準備中」でも計画に出し、代替完了パスを必ず持つ

### 4.4 コンプライアンスが後回しだと法人が買えない

自動送信・学習・ログ保管は、個人情報・機密・委託契約の問題になる。  
「便利な自動化」だけでは法務で止まる。

---

## 5. 競争戦略 — 厳しい指摘

### 5.1 大手が同じ言葉を使い始めたときの負け方

2026–2028 にかけて大手は必ず言う:

- “Agent that takes actions”  
- “Connect your apps”  
- “Ask and we’ll do it”

言語が同じだと、ブランドもモデルも配信も勝つ側に流れる。

MINERVOT が残る差異は言語ではない。 **業務の閉ループ所有**:

- 日本の商習慣に合わせた承認  
- 仕事履歴と証跡  
- 定期実行と失敗リカバリ  
- 「部分完了を完了と言わない」厳しさ  

ここをプロダクト仕様として強制できているかが戦略。

### 5.2 横に広げすぎると縦に負ける

SNSもWordも請求も予定も…と広げると、Copilot/Gemini の庭で薄く負ける。  
逆に「営業週報を、毎週、決まった品質で、保存と共有まで」など **縦の完了** で深く勝つ。

戦略提案:

1. まず 3 つの仕事タイプだけで Done 率 95% を取る  
2. その型を Smart Template 化する  
3. それから Capability を増やす  

### 5.3 「AI秘書」は感情ブランド、買う理由はオペレーション

ブランド言語は維持。  
営業資料・料金ページ・オンボーディングは **完了オペレーション** で書く。

## 6. 5年後も選ばれるための必須条件（優先順）

| 順位 | 条件 | なぜ |
|------|------|------|
| 1 | Decision→計画承認→証拠付き Done が一本道 | 体験の本体 |
| 2 | ICP を絞り、出口連携を少数精鋭で ready | 統合地獄を避ける |
| 3 | Work Memory が次回計画に自動注入 | 堀 |
| 4 | 単発/定期の信頼性（失敗・再開・重複禁止）が業務級 | 手放せなくなる |
| 5 | 監査・権限・テナントが法人に耐える | 単価と定着 |
| 6 | 完了率・再作業率の公開指標で改善し続ける | モデル競争から降りる |
| 7 | 「形式を選ばせるUI」を製品から消す | ツール比較を拒否 |

足りないものを綺麗に言うと「機能」ではない。  
**完了の強制、記憶の閉ループ、ICP の深さ、信頼の設計**が足りない。

---

## 7. MINERVOT が今すぐやめるべきこと

1. ChatGPT 比較の「より賢い回答」競争  
2. 形式ボタンを増やすロードマップ  
3. 未接続のまま「完了」を返すこと  
4. 全 SaaS 同時対応宣言  
5. Planner/モデル構成をユーザーに見せること  
6. 設計書だけの Done Definition（実装ゲートなし）

---

## 8. MINERVOT が今すぐ倍にするべきこと

1. 計画承認 UX（秘書が手順を考える体験）  
2. 完了証拠ゲート  
3. 類似仕事の再利用  
4. 失敗時の人間向け説明と再開  
5. 1–2 個の出口（例: Gmail 送付、Drive 保存）の完了品質  
6. 「仕事が終わった」通知の情報密度

## 9. 総合評価（辛口）

| 観点 | 点数(/10) | コメント |
|------|-----------|----------|
| 思想・ブランド | 8 | 方向は正しい。ツール集化を止め続ければ資産 |
| 現状実装の完了力 | 4 | 生成は進んでいるが出口と統一ゲートが弱い |
| UX の秘書感 | 5 | 依頼導線はあるが手段選択が顔を出す |
| データ堀 | 4 | 記憶基盤はある。Decision 閉ループが未完 |
| 競争耐性 | 3 | 大手エージェント物語に言語を奪われやすい |
| 事業として売れる明瞭さ | 4 | ICP と完了指標がまだぼんやり |

**総評:**  
「勝てる物語」は持っている。  
「勝っているプロダクト」にはまだなっていない。  

設計（Work + Decision Engine）を実装の強制力に落とし、  
狭い仕事タイプで完了率を取れなければ、5年後は「日本の素敵なAIチャット」として大手に吸収される側になる。
