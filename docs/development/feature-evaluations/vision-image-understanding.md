# 【ATLAS機能評価】画像理解（Vision）

機能名：MINERVOT 画像理解（OpenAI Responses API マルチモーダル）

ユーザー価値：レシート・請求書・表・営業資料・手書きメモなどを再入力せず、改善提案や Excel / Word / PDF 成果物まで一気通貫で進められる。

差別化：チャットで画像を見るだけでなく、構造化（VisionAnalysisResult）→成果物エンジン（ArtifactDocument）へ正式入力する秘書フロー。

繰り返し作業の削減：はい — 手入力OCR・表の写し・資料の読み取り改善の習慣作業を削減。

AI必要度：高 — 画像内文字・表・レイアウト理解に必要。前処理・用途ヒント・キャッシュ・コスト記録は通常プログラム。

AIなしで実装可能：一部 — リサイズ/EXIF/ハッシュ/権限/保存はAI不要。理解と構造化はAI必須。

運営コスト：画像1枚あたりテキストよりトークン増。detail自動切替・ハッシュキャッシュ・ecoで抑制。

外部APIコスト：有 — 既存 OpenAI Responses API のみ（新規OCR/OAuthなし）。

コスト削減案：

- [x] エコモードで足りるか（一般写真は auto/low）
- [x] まとめて生成できるか（バッチ解析→1成果物）
- [x] キャッシュ再利用できるか（contentHash + detail）
- [x] 予約実行にできるか（送信時のみ解析・選択だけでは実行しない）
- [x] AI起動条件を絞れるか（attachmentIds がある時のみ）
- [x] 外部APIの呼び出しタイミングを最小化できるか（前処理後・重複は再利用）
- [x] 完全自動ではなく承認後実行にできるか（文体保存は選択必須）
- [x] 同じ処理を再生成しない設計にできるか（ハッシュキャッシュ）

優先度：P0
