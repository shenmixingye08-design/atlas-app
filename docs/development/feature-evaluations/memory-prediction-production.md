# 【ATLAS機能評価】Memory / Prediction Production Integration

機能名：Memory / Prediction 本番統合（成果物差分で学習効果を証明）

ユーザー価値：同じカテゴリの成果物を繰り返すほど、追加指示・修正が減り、初回採用が上がる。毎回説明しなくても好みに近い成果物が届く。

差別化：Memory件数やUIスコアではなく、Word/Excel/PDF/PowerPointの実ファイル差分で改善を証明する。明示指示が常に優先され、1回修正では正式化しない。

繰り返し作業の削減：はい — 「毎回同じ文体・構成・形式・ファイル名を説明する」「同じ修正を繰り返す」習慣を削減

AI必要度：低〜中 — 好みの適用・優先順位・候補昇格・構造Diffは通常プログラム。文章の意味判断が必要な場面のみAI。

AIなしで実装可能：一部 — 優先順位解決・スコープ分離・exporter反映・Diff分類・昇格閾値・指標集計はAI不要。曖昧な好み抽出の一部のみAI候補。

運営コスト：生成ごとにMemory解決＋ledger記録（LLM追加呼び出しなし）。学習実験は評価モードのみ。

外部APIコスト：無（追加APIなし。既存生成パイプラインに構造化コンテキストを載せる）

コスト削減案：

- [x] エコモードで足りるか — Memory解決は決定論。AI再推論しない
- [x] まとめて生成できるか — 同一PersonalizationContextを複数形式に再利用
- [x] キャッシュ再利用できるか — owner×scope×categoryで解決結果をrun内再利用
- [x] 予約実行にできるか — 評価実験・バッチ学習は検証モードで予約実行可
- [x] AI起動条件を絞れるか — 候補提案のみ条件付き。適用自体はルール
- [x] 外部APIの呼び出しタイミングを最小化できるか — Memory適用で追加外部APIなし
- [x] 完全自動ではなく承認後実行にできるか — 高影響Memoryは承認必須
- [x] 同じ処理を再生成しない設計にできるか — appliedMemoryIds＋ledgerで再適用計測、二重正式化禁止

優先度：P0 — Phase成功条件そのもの。件数UIだけでは秘書価値を証明できない。
