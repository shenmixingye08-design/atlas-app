# 【ATLAS機能評価】実行型AI秘書リデザイン

機能名：実行型AI秘書（仕事完了オーケストレーション）への全体リファクタリング設計

ユーザー価値：ユーザーは形式ごとの「作成ボタン」を操作せず、仕事を依頼して待つだけで、生成・保存・送信・提出まで完了した状態で確認できる

差別化：ChatGPT / Claude / Gemini / Copilot は会話・生成が中心。MINERVOT は「依頼→自動連携→待機→通知→確認」で仕事を終わらせる専属秘書

繰り返し作業の削減：はい — 毎回の形式選択、途中操作、手動送信・保存、進捗確認のクリックを減らす。定期実行とテンプレート複製で習慣作業をさらに削減

AI必要度：中 — 依頼の理解・ステップ判断・文章生成のみ AI。スケジュール、状態遷移、リトライ、通知、承認ゲートは通常プログラム

AIなしで実装可能：一部 — ジョブ状態機械、cron、通知、履歴、複製、途中停止/再開はプログラム。自然言語の仕事分解と生成のみ AI

運営コスト：1仕事あたり既存 Commander + Orchestration と同程度。完了条件に外部連携を足しても AI 呼び出しは増やさない（連携は API）。エコモード / キャッシュ / 承認後実行で抑制

外部APIコスト：有 — OpenAI（生成・判断）、必要時のみ Google/Dropbox/X/メール等。呼び出しは仕事完了に必要なステップに限定

コスト削減案：

- [x] エコモードで足りるか — 定型定期仕事は eco / キャッシュ優先
- [x] まとめて生成できるか — 週次レポート等はまとめて生成→配信
- [x] キャッシュ再利用できるか — 同一依頼ハッシュの再生成禁止
- [x] 予約実行にできるか — Automation schedule を第一級
- [x] AI起動条件を絞れるか — スケジュール判定・ON/OFF・再実行可否は非 AI
- [x] 外部APIの呼び出しタイミングを最小化できるか — 承認後・必要ステップ到達時のみ
- [x] 完全自動ではなく承認後実行にできるか — 送信/公開/削除は承認ゲート
- [x] 同じ処理を再生成しない設計にできるか — 完了証拠 + idempotency key

優先度：P0 — ブランド差別化の根幹。ツール集化を止める方針文書と段階実装が必要
