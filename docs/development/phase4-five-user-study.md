## 0. 目的

本物のユーザー5名が、**説明なしで** MINERVOT を使えるかを検証する。

先生は実ユーザーだけ。開発者の好み・レビュー・推測は先生にしない。

---

## 1. 開発者の禁止事項（セッション中）

| 禁止 | 例 |
|------|-----|
| 操作説明 | 「ここに書いて」 |
| 口頭補足 | 「任せるを押すと進みます」 |
| 誘導 | 指差し、視線誘導 |
| ヒント | 「写真も送れますよ」 |
| 正解の教示 | 「そこ押してください」 |
| 仕様の弁護 | 「そういう仕様です」 |

許容発話は §3 のみ。それ以外は沈黙。録画は同意のうえ実施。

---

## 2. 対象・準備

| 項目 | 内容 |
|------|------|
| 人数 | **5名**（初回ユーザー優先。社内開発者・その配偶者は除外） |
| ビルド | セッション開始時に URL + commit SHA を記録。5人とも同一ビルド |
| デバイス | 本人の端末を優先。OS/ブラウザを記録 |
| 録画 | 画面 + 可能なら顔（同意必須） |
| 所要 | タスク最大15分 + 質問10分 |

---

## 3. テスト方法（厳密）

1. アプリを渡す（ログイン済み or ログイン画面から。どちらにしたかを記録）  
2. **これだけ伝える:**  
   > 「好きな仕事を頼んでください」  
3. 何も話さない  
4. 録画する  
5. 最後に §6 の質問をする（順番固定）

タイマー開始: ホーム（またはログイン直後の最初の画面）の first paint。

---

## 4. 観察項目（セッション中にタイムスタンプ必須）

| ID | 項目 | 記録方法 |
|----|------|----------|
| O01 | 最初に見た場所 | 最初5秒の主視線 / 指摘AOI |
| O02 | 最初に押した場所 | 最初のタップ対象 + ms |
| O03 | 迷った場所 | 最初の迷い（≥3秒停止 or 「わからない」）+ AOI + 発言 |
| O04 | 止まった時間 | 最長アイドル秒（および合計アイドル） |
| O05 | 戻るを押した回数 | ブラウザ戻る / UI戻る の合計 |
| O06 | 入力まで何秒 | first paint → 最初のキー/ペースト |
| O07 | 任せるまで何秒 | first paint → 「任せる」タップ |
| O08 | 途中離脱 | あり/なし。ありなら理由カテゴリ |
| O09 | 仕事完了 | あり/なし（未補助で成果物を開けた） |
| O10 | 笑った瞬間 | 時刻 + 画面トリガー。なければ `none` |
| O11 | 驚いた瞬間 | 時刻 + トリガー。なければ `none` |
| O12 | イライラした瞬間 | 時刻 + トリガー。なければ `none` |

### AOI（固定）

`Brand` / `Headline` / `Input` / `任せる` / `写真を添える` / `Other` / `Outside`

### 迷いテーマ（事後コーディング・閉じた集合）

- `dont_know_what_to_type`
- `dont_know_photo`
- `too_many_options`（出てはいけないが観察用）
- `wait_anxiety`
- `completion_unclear`
- `other:<短文>`

## 6. 終了質問（順番固定・読み上げ文言そのまま）

① 何をするサービスだと思いましたか？

④ 一番分からなかったところは？

質問中も製品の説明・弁護は禁止。

## 7. 改善ルール（人数ゲート）

迷いテーマごとに、5人中何人がそのテーマで迷ったかを数える。

| 人数 | アクション |
|------|------------|
| **1人だけ** | **改善禁止**（個人差として記録のみ） |
| **3人**（以上、かつ5人未満） | **改善する**（P1候補） |
| **5人全員** | **最優先で改善**（P0） |

補足:

- 2人 → P2（改善は可能だが優先は下げ、実データ再確認後）
- 完了率・980円・紹介意図は「迷い」とは別集計（§8）

**禁止:** 開発者の好み / レビュー感想 / 推測での改善起票。
