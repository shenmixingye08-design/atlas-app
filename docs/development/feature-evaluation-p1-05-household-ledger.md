# 【ATLAS機能評価】P1-05 家計簿専用テーブル化

機能名：家計簿明細の専用 DB テーブル化（Single Source of Truth）

ユーザー価値：レシート登録・手動登録した明細が再起動・再デプロイ・複数 instance でも消えず、件数上限なく検索・集計・再利用できる。習慣的な再入力・再アップロードを減らす。

差別化：チャットログや JSON blob に頼らず、秘書として家計を永続記憶する。古い明細の勝手な切り捨てをしない。

繰り返し作業の削減：はい — 再登録・再確認・「消えた明細の作り直し」を削減

AI必要度：不要 — 永続化・ownership・ページング・backfill は通常プログラム。AI は既存のレシート解析のみ（本変更の対象外）。

AIなしで実装可能：はい — repository + SQL + RLS deny-all + service role

運営コスト：AI 追加呼び出しなし。DB 読み書きのみ。移行時の一度きりの backfill。

外部APIコスト：無（Supabase 既存枠内）

コスト削減案：

- [x] エコモードで足りるか — AI 不使用のため該当なし（永続化は常時低コスト）
- [x] まとめて生成できるか — 一覧・月次集計は DB クエリで一括取得
- [x] キャッシュ再利用できるか — process 内は hydrate 済みフラグのみ。正本は DB
- [x] 予約実行にできるか — backfill は初回 hydrate / probe 時に安全実行
- [x] AI起動条件を絞れるか — 本機能は AI を起動しない
- [x] 外部APIの呼び出しタイミングを最小化できるか — 解析失敗時は明細 0（P0-01 維持）
- [x] 完全自動ではなく承認後実行にできるか — 低信頼レシートは既存の確認フロー維持
- [x] 同じ処理を再生成しない設計にできるか — upsert by id / backfill idempotent

優先度：P1
