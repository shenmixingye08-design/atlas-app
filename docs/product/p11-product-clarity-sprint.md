# P11 Product Clarity Sprint

## 【ATLAS機能評価】

機能名：P11 プロダクト明確化（初回30秒価値伝達・導線整理）

ユーザー価値：初めて見た人が30秒で「仕事が終わる」と理解し、初回5分で1件の完成体験まで到達できる

差別化：ChatGPT＝会話 / MINERVOT＝仕事完了を1画面で対比し、会話ツールではなく代行完了プロダクトとして伝わる

繰り返し作業の削減：はい — 初回の迷い・説明読み・形式選択・途中離脱を減らし、最初の1依頼完了までの操作を最短化する（新機能は追加しない）

AI必要度：不要 — コピー・導線・表示条件・測定済み時間の表示のみ。新規AI呼び出しなし

AIなしで実装可能：はい — UI/文言/オンボーディング順序/progressive disclosure/実測時間表示

運営コスト：追加AI呼び出しなし。localStorage判定と既存 first-experience の再利用のみ

外部APIコスト：無

コスト削減案：

- [x] エコモードで足りるか — AI不使用のため該当なし（UIのみ）
- [x] まとめて生成できるか — 初回は1依頼に限定し、追加生成を促さない
- [x] キャッシュ再利用できるか — 既存 onboarding / first-experience 状態を再利用
- [x] 予約実行にできるか — 初回導線は即時1件完了を優先（予約は後段）
- [x] AI起動条件を絞れるか — 初回説明ウィザードの多段AI説明を廃止し、実依頼へ直行
- [x] 外部APIの呼び出しタイミングを最小化できるか — 形式選択・連携誘導を初回から外す
- [x] 完全自動ではなく承認後実行にできるか — 仕事選択後に依頼実行（既存どおり）
- [x] 同じ処理を再生成しない設計にできるか — firstExperienceCompleted 後は再表示しない

優先度：P0 — 初回登録率・依頼完了率・継続率に直結。機能追加なしで価値伝達を最大化

---

## 改善方針（機能追加禁止）

既存の依頼・初回体験・完了画面・測定時間だけを使い、見せ方と順序を変える。

---

## 改善前後の比較

| 観点 | Before | After |
|------|--------|-------|
| ホーム／LP第一声 | 「あなた専属のAI秘書」 | 「あなたの仕事を代わりに終わらせます」 |
| ChatGPT差分 | 暗黙（チャットではない、と説明） | 1画面で ChatGPT＝会話 / MINERVOT＝仕事が終わる |
| 初回導線 | 5ステップ説明 → 初回体験を defer | 1画面歓迎 → 仕事を選ぶ → 1回依頼 → 完成 |
| 初期UI | Word/Excel/PDF/添付が常時表示 | 必要になるまで非表示（progressive disclosure） |
| 成功体験 | 完了時間（秒）のみ | 実測完了時間 + 手作業目安との差分（嘘の数値なし） |
| LP構成 | 機能カード／AIチーム／ダッシュボードが上位 | 価値 → 3ステップ → 依頼例 → 料金。詳細は後方 |

## UX改善理由

1. **カテゴリ誤解の除去** — 「AI秘書」は役割名で、ベネフィットではない。初見は「仕事が終わる」成果を先に伝える。
2. **認知負荷の削減** — 形式選択・通知・複数機能は初回の完了に不要。選択肢を減らすと依頼完了率が上がる。
3. **途中離脱の削減** — 説明ウィザード5段は「まだ価値を体験していない」状態でタップを増やす。完成までを最短にする。
4. **差別化の可視化** — ChatGPT比較を抽象説明ではなく対比UIにし、30秒以内にカテゴリ差を理解させる。
5. **成功の証拠** — 完了時に実測時間と削減目安を見せ、継続の理由を感情ではなく成果で残す。

## 期待できる改善効果（指標）

| 指標 | 上がる理由 |
|------|------------|
| 初回登録率 | LP第一画面で「使いたい理由」（仕事が終わる）とChatGPT差分が同時に伝わる。機能カタログではなく完了体験を約束する。 |
| 依頼完了率 | 登録後すぐ「仕事を選ぶ→依頼→完成」。形式選択・説明スキップが減り、最初の1件完了までのタップ数が最短化。 |
| 継続率 | 初回に必ず完成体験があり、削減時間（実測ベース）が見える。次回も「また終わらせられる」期待が残る。 |

> 見た目の洗練が目的ではない。1000人に「これ使いたい」と思わせ、最初の完成まで届けることが目的。
