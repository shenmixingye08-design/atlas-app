# 【ATLAS機能評価】P1-01 PDF表描画 + 欠落時fail

機能名：PDF表描画 + 欠落時fail-closed（P1-01）

ユーザー価値：表付き報告書のPDFで表が欠けず届き、「できた」のに表がない手戻りがなくなる

差別化：Word/Excelと同等に表を保持し、欠落を成功扱いにしない

繰り返し作業の削減：はい — PDFを開き直して表を手で直す／再依頼する習慣作業を削減

AI必要度：不要 — 既存markdown表ブロックを決定的に描画・検証するだけ

AIなしで実装可能：はい — pdf-lib描画 + ソース表件数 vs 描画件数ゲート

運営コスト：追加AIなし。描画CPUのみ（既存PDF生成と同オーダー）

外部APIコスト：無

コスト削減案：

- [x] エコモードで足りるか — AI不使用のため該当なし（低コスト）
- [x] まとめて生成できるか — 既存 multi-format export のまま
- [x] キャッシュ再利用できるか — 成功PDFの表欠落サイレント再生成はしない
- [x] 予約実行にできるか — 該当なし
- [x] AI起動条件を絞れるか — AI起動しない
- [x] 外部APIの呼び出しタイミングを最小化できるか — 外部APIなし
- [x] 完全自動ではなく承認後実行にできるか — 決定的レンダリング（承認不要）
- [x] 同じ処理を再生成しない設計にできるか — 欠落時は失敗として再試行、成功後の表欠落は不可

優先度：P1（公開品質 / 優先度B）
